## 审查结论核实

| 审查项 | 核实结果 | 处理 |
| --- | --- | --- |
| P0 设置菜单弹出位置错误 | **属实**。`settings-menu.show({x: title-settings.x, y: title-bar.height})` 把按钮在父布局中的坐标当作 ContextMenuArea 自身局部坐标，双重偏移（与截图现象吻合；ContextMenuArea.show 坐标相对该元素，同文件其余右键菜单均以元素局部鼠标坐标调用且行为正确） | 已修：`show({x: 0px, y: parent.height})`，菜单锚定按钮下沿，左/右键两条路径 |
| P0 顶部分组栏 `▼` 功能错误 | **属实**。注释称"分组过多时的下拉入口"，实际点击调用 `group-create-requested()`（新建分组） | 已修：改为真实下拉菜单——列出全部分组（当前分组打勾）+ 分隔线 + 新建分组 |
| P0/P1 分类删除迁移缺陷 | **属实且比审查所述更重**。①迁移下拉使用全部 `category_rows()`，包含被删分类自身（模型层有 source==target 守卫不会损数据，但用户可选中无效项）；②按**名称**匹配目标，同组重名分类会错绑；③**"删除项目"按钮读取的 `dialog_target` 在删除路径从未赋值**，会作用于过期目标（重命名对话框遗留值）或静默无效 | 已修：删除路径写入目标 id；迁移列表排除被删分类并改为索引↔id 列表；无其他分类时禁用迁移按钮；模型守卫补回归断言 |
| P1 标题栏按钮不统一 | **属实**。搜索/固定为自适应宽度 Text，设置为固定 44×24 Rectangle，命中区宽度、间距、"固定"→"已固定"宽度变化均不一致；标题栏高度已是 44px | 已修：统一 36×32 命中区（圆角 6、hover 背景、12px 文字垂直水平居中）、4px 间距、右缘 8px；固定按钮固定宽度（12px 字号下"已固定"三字恰为 36px），状态切换不再影响布局 |
| P1 底部"视图、排序、添加"无功能 | **属实**（"备份"已有功能，其余为纯文本） | 已修：视图=图标三档菜单（新增 controller `set_icon_size` 持久化，非法值归一化）；排序=四模式菜单；添加=既有 `grid-add-requested`（新建项目）；备份入口统一同款 36×24 hover 命中区 |
| P1 设置菜单过长、无分区 | **属实**（27 项平铺） | 已修：重构为子菜单（主题/强调色/透明度/圆角与背景/排序）+ 分隔线 + 顶层功能项；并接入 `checkable/checked` 当前状态打勾（快照由 refresh_ui 同步：主题/强调色/透明度/圆角/背景/排序/图标档位/Everything/更新开关） |
| P1 分组栏横向滚动 | 属实未实现 | 本轮未做横向滚动；▼ 下拉已提供全部分组切换，彻底方案（滚动 + 拖放命中同步）另行安排 |
| P2 组合列表无选中高亮 | **属实**（状态已维护但行背景恒透明） | 已修：选中行 accent 底色 + 文字强调色，hover 反馈 |
| P2 状态栏拥挤/截断 | **属实** | 已修：左侧计数文本 `horizontal-stretch + elide`，右侧校验状态 `max-width 260px + elide`，入口固定宽度 |
| P2 默认示例含失效路径 | 属实（演示角标功能的设计） | 未改（基线示例库内容，改动会破坏示例库断言；建议后续任务处理） |
| P2 默认图标区分度 | 属实 | 未改（需图标资源设计，另行安排） |
| P1 透明度可读性保护 | 属实（高透明下文字对比下降属预期行为） | 未改（可读性保护方案另行安排） |

  鼠标坐标调用且实测正确；弹出实现为 muda 0.19.3（`TPM_LEFTALIGN`，菜单自锚点向下展开，

  MenuItem 有 `checkable`/`checked`）；`for` 生成 MenuItem 编译验证通过。
